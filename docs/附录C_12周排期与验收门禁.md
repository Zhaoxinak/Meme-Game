# 附录 C · 12 周排期与验收门禁
## 《脑洞军团大乱斗》v4 落地计划

> **假设**：一人 + AI 协作，**每周有效开发 20h**，12 周共 **240h**。
> AI 协作能显著加快"写代码"，但**不能**加快"调试、调优、playtest、做决策"——所以工时估算按保守值给。

## C1. 先说一个不愉快的事实：240 小时装不下全部内容

把所有想做的加起来：

**已经超了，而且 Playtest 和缓冲是 0。** 这两项是"上线品质"的来源，不能为 0。

### C1.1 解法：承诺线 / 冲刺线

把所有工作切成两层。**承诺线是"上线必须有"，冲刺线是"有余力再加"。**

| 层 | 工时 | 定义 | 排期地位 |
|---|---|---|---|
| **承诺线** | **184h** | 做完就能上线，且达到商用基本盘 | **W1-W9 必须完成**，含 4 个门禁 |
| **冲刺线** | **66h** | 做完能显著提升竞争力和传播力 | W10-W12 按剩余时间依次补 |
| **缓冲** | 隐含 | 每周预留 2h 机动 | 见 C6 |

> **规则：冲刺线的每一项都可以被单独砍掉，砍掉后游戏仍可上线。**
> 这条规则是排期能扛住意外的唯一保障。

**存档结构设计**：

```js
const SAVE_V1 = {
  version: 1,
  settings: { volMaster: .85, volBgm: .45, volSfx: .70, volUi: .55, speed: 1 },
  stats:    { games: 0, bestWave: 0, totalKills: 0, wins: 0 },
  meta:     { exp: 0, level: 1, points: 0, spent: {} },   // 天赋树
  codex:    { seen: {}, used: {} },                        // 图鉴（v5）
};

function loadSave() {
  try {
    const raw = localStorage.getItem("nd_legion_save_v1");
    if (!raw) return structuredClone(SAVE_V1);
    return migrate(JSON.parse(raw));
  } catch (e) { return structuredClone(SAVE_V1); }
}
function migrate(save) {
  // 未来结构变更时的迁移链：v1→v2→v3…
  // 铁律：永远保留旧字段读取路径，宁可冗余不可毁档
  return save;
}
```

**W4 验收**：
- [ ] 刷新页面所有设置保持
- [ ] 手动把 `version` 改成一个不存在的值 → 不崩溃，回落到默认存档
