## 四、"路径也有问题" 的修法

单文件 HTML 引图的两条路：

- **方案 A（推荐）· base64 内嵌**：把精灵转成 data URI 写进 `src/assets.js`，
  build.js 把它拼进 HTML。仍是单文件、双击即开、**永不踩路径**。代价：HTML 体积变大。
- **方案 B · 外部 assets/ 目录**：建 `assets/` 放 png，build.js 增加拷贝步骤。
  开发清爽，但交付必须带文件夹，相对路径易错（这正是你现在踩的坑）。

> 你现在的「路径问题」本质是：引图没有任何机制，相对路径在单文件/不同目录下必然 404。
> 接素材前先定方案，否则换了图还是打不开。

## 六、素材怎么接进本项目（外部 assets/ 方案，已落地）

已按你选的方案搭好管线，build 时把 `assets/` 拷到产物同级。

### 本次已接入映射（已落地，18 张动画表 · v2）

每张 PNG 是 **5 行 x 8 帧**的动画精灵表（768x480，整帧 2x NEAREST 放大）：
行序 = 站立 / 走动 / 攻击 / 受击 / 死亡。渲染端按单位状态自动播放，
死亡播完停最后帧（躺倒）再淡出；nearest 缩放保持像素锐利。

> 选取理由：Pixel Chibi 是清单里「最像开罗」且真正免费可商用的角色包。
> 源素材本身网格对齐（pivot bottom-center），因此 v2 不再逐帧裁剪（那会造成帧间抖动），
> 而是整帧 2x 放大 + HSL 换色（保留明暗梯度），18 张表合计仅约 250KB。
> 骑兵线单独合成：Pixel Chibi 小人做骑手 + Horse Pixel Art Animation（CC0）马序列，
> 先画骑手、再画马身盖住腿部，得到"骑在马上"的侧身战斗姿态。
> knight 源表缺 DAMAGED 行，其受击行用 ATTACK 帧补齐（渲染端另有白闪反馈）。

1. 把小人 PNG 丢进 `assets/units/`，命名见 `assets/units/放置说明.txt`：
   - 最简起步：`player_melee.png` / `player_ranged.png` / `player_cavalry.png` + 同款 `enemy_*`
   - 想精细：`player_melee_L1.png … L5.png` 等（按等级换皮）
   - 背景可选：`assets/bg.png` 覆盖程序化棋盘格
2. 根目录执行 `node build.js` → 生成 `脑洞军团大乱斗.html` 并把 `assets/` 拷到同级。
3. 一起分发 `html` + `assets/` 文件夹即可。**图缺失不崩**：自动回退程序化小人。

> 精灵以「脚底中心」为锚、按世界高度缩放（透视由 `applyWorld` 负责）；
> 朝向靠 `scale(facing,1)` 翻转，所以图只要画「朝右」一套即可。

## 七、"路径也有问题" 已修（单位走位显示）

根因：`update.js` 里单位是 **轴对齐 `Math.sign` 8 方向步进**，且 y 方向硬乘
`0.6` 减速；而渲染时 `applyWorld` 对 y 做了**非线性透视投影**。两套坐标系对不上 →
单位在屏幕上**朝向偏掉、走位呈楼梯状、远近速度错位**。

修法：新增 `stepToward(u, mx, my, dt)`，改为**世界空间内沿目标方向的归一化匀速步进
（x/y 同速）**，纵深观感完全交给投影。只动移动几何，**不动任何战斗/数值**；
同阵营 soft-repulsion 与击退不受影响。

⚠️ 这是基于代码的推断修复，未在真机逐帧回放验证——请你 build 后实际打一局看走位是否顺了。
若仍有「歪」的感觉，多半是 `drawSpriteUnit` 的锚点/朝向需要按你实际素材微调。
