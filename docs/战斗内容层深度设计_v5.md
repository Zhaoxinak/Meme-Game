# §0. 前置修复：4 处绕开 `modsOf()` 的硬编码

## 0.1 问题

`state.js:14` 定义了正确的取增益方式：

```js
const modsOf = side => (side === "player" ? G.mods : G.enemyMods);
```

`update.js:388` 的 `aiDrawPerk()` 也在认真给 AI 抽卡：

```js
function aiDrawPerk() {
  const p = PERKS[Math.floor(Math.random() * PERKS.length)];
  p.apply(G.enemyMods);   // ← 写进去了
  G.aiPerk = p.name;
}
```

**但读取端有 4 处绕开了 `modsOf()`**，把 `G.enemyMods` 当空气：

| # | 位置 | 代码 | 后果 |
|---|---|---|---|
| 1 | `state.js:81` | `const hpMul = side === "player" ? G.mods.hpMul : 1;` | AI 抽到「铁血纪律 +15% 生命」→ **0 效果** |
| 2 | `state.js:115` | `const bonus = side === "player" ? G.mods.sizeBonus : 0;` | AI 抽到「以众凌寡 +1 兵/系」→ **0 效果** |
| 3 | `utils.js` `counterMul` | `if (m <= 1 \|\| atk.side !== "player") return m;` | AI 抽到「克敌机先 克制+15%」→ **0 效果** |
| 4 | `combat.js:52` | `const scMul = u.side === "player" ? G.mods.skillChanceMul : 1;` | AI 抽到「暴躁老哥 大招率+50%」→ **0 效果** |

**6 张战术卡里，对 AI 真正生效的只有「全军突击」（atkSpdMul）一张。** 其余全部是死数据。

## 0.2 这不是理论问题，是已测出的病

`state.js:28-29` 的注释自己写着：

> 早期只有玩家有增益，等于战术是纯白赚——**实测「随机乱选」也能打出 67% 胜率**

现在 AI 会抽卡了，注释宣称"双方战术增益数量对等"。**但只有 1/6 生效，等于病没治好，只是从"AI 没卡"变成了"AI 的卡 5/6 是废纸"。**

## 0.3 修复方案（每处 3 行，共 12 行）

```js
// 1. state.js:81
const hpMul = modsOf(side).hpMul;

// 2. state.js:115
const bonus = modsOf(side).sizeBonus;

// 3. utils.js counterMul 末尾
if (m <= 1) return m;
return m * (1 + (modsOf(atk.side).counterBonus || 0));

// 4. combat.js:52
const scMul = modsOf(u.side).skillChanceMul;
```

**注意：`counterMul` 与 `attack()` 位于 `utils.js` / `combat.js`，都在 `state.js` 之后构建，可以安全引用 `modsOf`。**（依赖方向见 CLAUDE.md：config → state → utils → combat，禁止反向引用。）

## 0.4 修复后的验证

| 检查 | 方法 | 通过线 |
|---|---|---|
| 增益双侧生效 | 控制台强制 `G.enemyMods.hpMul = 2`，生成敌方单位 | 敌人血量 ×2 |
| 胜率回归 | 镜像模式跑 200 局（同阵容同卡） | 胜率 **50% ± 4%** |
| 随机乱选胜率 | 竞技场随机选卡跑 200 局 | **从 67% 降到 52-56%** |
| 不回退 | `node tests/*.js` | 全绿 |

> **最后一条才是真正的验收。** 如果修完之后"随机乱选"还是能打出 65%+ 胜率，
> 说明还有别处的隐藏不对称没找到——继续挖，不要接受这个数字。

## 0.5 为什么这必须排在英雄之前

英雄的本质是**玩家侧的一坨新增益**（光环 + 技能）。
如果增益通道本身是坏的，英雄的所有收益都会自动落到"玩家白赚"那一侧——
你会得到一个"装上英雄就赢、不装就输"的系统，然后花三个月去调一个根本不该存在的数值。

**先修水管，再开水龙头。**

# §1. 本层的设计目标

## 1.1 这四块分别服务哪条 Pillar

| 系统 | 主服务的 Pillar | 它要解决的那个"不对劲" |
|---|---|---|
| **兵种深度** | P2 军团成长可见 | 打完 20 波，兵还是那 3 种脸，后期只剩"数字变大" |
| **双轴克制** | P3 钱永远不够花 / P1 看得懂 | 只会一种配兵也能通关，克制形同虚设 |
| **经济纵深** | P3 | 后期金币溢出无处花，经营决策在第 10 波后就消失 |
| **英雄系统** | P2 + P3 | 缺一个"属于我的东西"——没有情感投射对象 |

## 1.2 一句话：这四块是一件事，不是四件事

> **英雄系统是经济系统的新 sink，经济系统的深度来自兵种与克制的决策密度。**

拆开做会互相打架，一起做是**正向耦合**：

```
兵种变多 → 克制组合变多 → 配兵决策变密 → 经营更烧脑
                                    ↓
                          后期金币溢出（现有问题）
                                    ↓
                    英雄养成吃掉溢出金币（新 sink）
                                    ↓
                      经济重新紧张 → 决策持续有效
```

**这就是为什么"加英雄"不只是加内容，它顺手解决了 v3 企划担心了很久的通胀问题。**

# §2. 兵种深度

## 2.1 现状盘点（实测）

| 层 | 现状 | 代码位置 |
|---|---|---|
| 基础系 | 3 个（melee / ranged / cavalry） | `UNIT_DEFS` |
| 等级 | Lv1-Lv5，每级 HP ×1.28 / ATK ×1.32 | `CONFIG.lvHpMul` |
| 分支 | 每系 2 条（反转 ×2.6 / 专精 ×2.4），Lv3 起生效 | `BRANCHES` |
| 命名 | 3 系 × 5 级 = 15 个名字，分支覆盖 Lv3-5 | `SKILL_NAMES` + `BRANCHES[].names` |
| 外观 | 头盔/武器/坐骑三件套查表装配 | `KAIRO` + `BRANCHES[].kits` |
| 守城特殊编制 | sapper / medic / mage（走 `u.spec`） | `SHOP.units` + `combat.js` |
| 大招 | 每系每级一条，共 15+18 条 | `SKILLS` + `BRANCHES[].skills` |

**诊断**：横向（系别）已经很扎实——三元环 + 六分支是本作最好的设计，别动它。
**纵向（每个系内部的差异）和"系外"（特殊定位）是空的。**

## 2.2 红线：不加第 4 个基础系

三元环 `近战→骑兵→远程→近战` 是全部平衡的地基。加第 4 个基础系 = 环直接崩，
`COUNTER` / 分支专克 / `atkMulVs` / 玩家的心智模型全部要重写。

**深度不靠加系，靠加"轴"。** 这就是 §2.3。

## 2.3 ★核心设计：双轴克制（攻击类型 × 护甲类型）

### 2.3.1 为什么要第二根轴

现状只有一根轴：**兵种 vs 兵种**（3×3 三元环）。

它的局限：所有近战打所有目标都是一个倍率。玩家没法区分"用剑砍"和"用锤砸"。

加第二根轴后，同一个兵种打不同护甲的目标有不同效果——**克制从"3 选 1"变成"看兵种 + 看护甲"两层判断**。

### 2.3.2 攻击类型（5 种）

| Key | 名称 | 来源武器 | 设计语言 |
|---|---|---|---|
| `slash` | 斩击 | 剑、刀、镰、斧 | 砍肉快，砍铁砍墙都不行 |
| `pierce` | 穿刺 | 矛、枪、箭、弩、激光 | 穿甲，中等 |
| `blunt` | 钝击 | 棒、锤、盾击、拳 | **砸重甲最疼**，够不着远程 |
| `magic` | 魔法 | 法师、部分大招 | 无视护甲，但拆不动建筑 |
| `siege` | 攻城 | 攻城器、爆破手自爆 | **只拆建筑**，打架很废 |

### 2.3.3 护甲类型（5 种）

| Key | 名称 | 覆盖单位 |
|---|---|---|
| `none` | 无甲 | Lv1 洞穴人、法师、医师、爆破手 |
| `light` | 轻甲 | 远程系全系、飞镰游骑、斥候 |
| `heavy` | 重甲 | 大盾步兵、枪骑兵（Lv4+）、铁浮屠、机甲系 |
| `struct` | 建筑 | 城墙三段、主城、攻城器 |
| `hero` | 英雄 | 双方英雄单位 |

### 2.3.4 克制矩阵

行 = 攻击类型，列 = 护甲类型：

| AT ↓ \ 护甲 → | 无甲 | 轻甲 | 重甲 | 建筑 | 英雄 |
|---|---|---|---|---|---|
| **斩击 slash** | **1.25** | 1.00 | 0.75 | **0.35** | 1.00 |
| **穿刺 pierce** | 1.00 | **1.25** | 1.00 | 0.50 | 1.00 |
| **钝击 blunt** | 1.00 | 0.75 | **1.25** | 0.75 | 1.00 |
| **魔法 magic** | 1.00 | 1.00 | **1.20** | 0.50 | **0.85** |
| **攻城 siege** | 0.50 | 0.50 | 0.75 | **2.00** | 0.75 |

**每个数字的 rationale**：

| 格子 | 值 | 理由 |
|---|---|---|
| 斩击 → 无甲 1.25 | 高 | 常识：刀砍没穿衣服的人最有效 |
| 斩击 → 重甲 0.75 | 低 | 常识：砍铁砍不动。**这是本作最重要的一个"常识教学"** |
| 斩击 → 建筑 0.35 | 极低 | **解释"为什么剑士拆墙慢"**。让玩家直觉理解城墙不是靠人多就能拆的 |
| 穿刺 → 轻甲 1.25 | 高 | 箭射皮甲 |
| 钝击 → 重甲 1.25 | 高 | 常识：锤子砸铁砧——**震伤，甲越厚越疼** |
| 钝击 → 轻甲 0.75 | 低 | 轻甲灵活，吃不住实锤反而躲得快 |
| 魔法 → 重甲 1.20 | 高 | 无视护甲，但**低于钝击的 1.25**，避免魔法成为重甲唯一解 |
| 魔法 → 英雄 0.85 | 低 | **英雄抗魔**。防止法师 + 爆发直接秒英雄（见 §5.6） |
| 攻城 → 建筑 2.00 | 极高 | 攻城器的全部存在理由 |
| 攻城 → 单位 0.50 | 低 | **防止攻城器当主力打架**。它必须是一个"专职"单位，不是万能单位 |

**矩阵平衡自检**：每行之和 = 无甲 + 轻甲 + 重甲（排除建筑/英雄两个专职列）

| 攻击类型 | 常规三列之和 | 判定 |
|---|---|---|
| 斩击 | 1.25 + 1.00 + 0.75 = **3.00** | ✅ |
| 穿刺 | 1.00 + 1.25 + 1.00 = **3.25** | ⚠️ 略高 |
| 钝击 | 1.00 + 0.75 + 1.25 = **3.00** | ✅ |
| 魔法 | 1.00 + 1.00 + 1.20 = **3.20** | ⚠️ 略高 |

> 穿刺与魔法略高是**刻意的**：它们都需要前置条件（穿刺要远程站位、魔法要走特殊编制），
> 不像斩击/钝击那样"自带就是"。**用获取成本换倍率**，这是标准的平衡手法。
> `[PLACEHOLDER · 若实测穿刺流统治战场，1.25 → 1.15，矩阵和降到 3.15]`

### 2.3.5 双轴如何叠加在三元环之上

```js
function damageMul(atk, def) {
  const ring   = counterMul(atk, def);              // 现有三元环 + 分支专克
  const matrix = AT_VS_ARMOR[atk.atkType][def.armorType];
  return ring * matrix;                              // 相乘
}
```

**倍率区间**：

| 情形 | 计算 | 结果 |
|---|---|---|
| 全打对（三元环克 + 专克分支 + 打对护甲） | 2.6 × 1.25 | **×3.25** |
| 只吃三元环 + 打对护甲 | 1.35 × 1.25 | **×1.69** |
| 中性 | 1.0 × 1.0 | **×1.00** |
| 全打错 | 1.0 × 0.75 | **×0.75** |

**从 ×0.75 到 ×3.25，跨度 4.3 倍。** 对比现状（×1.0 到 ×2.6，跨度 2.6 倍）——决策权重提升 65%。

### 2.3.6 ⚠️ P1 风险：30v30 混战里玩家算得清 5×5 矩阵吗

**算不清，也不需要算清。** 这是设计的关键：

> **矩阵必须由常识驱动，而不是让玩家背表。**

三个能被直觉理解的规则，覆盖 80% 场景：

| 常识 | 对应格子 | 玩家心智 |
|---|---|---|
| "砍墙没用" | 斩击→建筑 0.35 | 不用教 |
| "锤子砸铁最疼" | 钝击→重甲 1.25 | 不用教 |
| "攻城器只拆墙" | 攻城→建筑 2.0 / →单位 0.5 | 不用教 |

**剩下的靠可视化**（§3.2），不靠玩家记忆。

> **反例（不要做）**：把矩阵做成一张需要查表的"攻略要素"。
> 那会让新手在前 10 分钟就放弃，且违反 P1「看得懂的混乱」。

### 2.4.2 六分支（叠加攻击/护甲类型）

| 分支 | 系 | 攻击类型 | 护甲类型 | 设计意图 |
|---|---|---|---|---|
| 大盾步兵 shield | 近战 | blunt（盾击） | **heavy** | 盾牌砸人 = 钝击；本身重甲 → **钝击打重甲 1.25，而它自己就是重甲，形成"重甲内战"** |
| 斩马刀 blade | 近战 | slash | light | 纯输出，脆 |
| 狙击手 sniper | 远程 | pierce | light | 高倍穿刺 |
| 箭雨手 volley | 远程 | pierce | light | 同上，靠数量 |
| 枪骑兵 lancer | 骑兵 | pierce | **heavy** | 冲锋穿刺 + 重甲 |
| 飞镰游骑 scythe | 骑兵 | slash | light | 镰刀 = 斩击，切轻甲（远程） |

> **大盾步兵的精妙之处**：它是 blunt + heavy。
> 钝击 → 重甲 1.25，而它自己是重甲 → **敌方重甲打它（钝击）也是 1.25**。
> 于是"重甲对撞"变成互相加伤的高速消耗战，而不是两个肉盾互相挠痒。
> 这解决了塔防/自走棋里最常见的"双方都堆肉 → 局面僵死"问题。

| 2 | **医师** medic | — | none | 攻击改为治疗最残血友军（heal = atk×1.6） | 续航 | 骑兵冲/落雷点 |
| 3 | **法师** mage | **magic** | none | 普攻挂 burn + 小范围溅射 | 破重甲 | 近战贴脸 |
| 4 | **鼓手** bard 🆕 | blunt | none | 光环 r=140：友军攻速 ×1.15 | 团队核心 | **谁都想先杀他**（HP 仅远程 70%） |
| 5 | **斥候** scout 🆕 | pierce | light | 移速 ×1.4；开局 3s 给敌方全体 slow 0.75 | 先手节奏 | 杀不死也不亏 |
| 6 | **毒师** poisoner 🆕 | magic | none | 普攻挂 poison（可被净化） | 破治疗流 | 医师净化 |

**为什么这 8 个不进三元环**：全部走"中性 ×1"（打谁 ×1、被谁打 ×1），靠独特机制立足。
**这条红线来自 v2 原则 6，必须守住——一旦某个特殊编制进了克制环，三元环的平衡就要重算。**

### 2.4.4 守城模式的兵种投放节奏

| 波次 | 解锁 |
|---|---|
| W1 起 | 近战 / 远程 / 骑兵 |

## 2.5 老兵晋升（承接 v4 的 M6）

| 击杀 | 称号 | 加成 | 外观 |
|---|---|---|---|
| 2 | 老兵 | 攻击 ×1.10 | 头盔加羽饰 |
| 4 | 精锐 | 攻击 ×1.20、HP ×1.15 | 头盔描金边 + 肩甲 |
| 6 | **战场传说** | 大招触发率 ×1.5、攻击 ×1.30 | 金色描边 + 头顶星标 + 拖尾 |
| 传说阵亡 | — | 对方全军 slow 1s（哀兵） | 全屏大字「传说陨落」+ 慢动作 |

**晋升与双轴的一个联动点**（这是让系统互相咬合的细节）：
升到「精锐」的单位**护甲类型升一档**（none → light，light → heavy）。

理由：视觉上"加肩甲/描金边"了，机制上就该更抗打——**外观与数值必须同步变化，否则玩家会觉得晋升是假的**。这是 P2 支柱的严格兑现。

# §3. 克制系统深化

## 3.1 三层克制全景

```
第一层：三元环（粗）        近战 → 骑兵 → 远程 → 近战      ×1.35
第二层：分支专克（中）      反转 ×2.6 / 专精 ×2.4
第三层：攻防类型（细）      5 攻击 × 5 护甲                ×0.35 ~ ×2.00
────────────────────────────────────────────────────
最终倍率 = 三层相乘，区间 ×0.75 ~ ×3.25
```

## 3.2 可视化：让玩家"看见"克制（P1 支柱的兑现）

现状只有 `popCounter()` 在倍率 ≥2 时飘一个"克制!"。三层克制上线后，需要一个分级反馈：

| 最终倍率 | 飘字 | 颜色 | 附加反馈 |
|---|---|---|---|
| ≥ 2.5 | **「完克！」** | 金 #ffd479 | 顿帧 100ms + 屏震 4px |
| 1.6 ~ 2.5 | **「克制！」** | 品红 #ff5ad8 | 顿帧 60ms |
| 1.15 ~ 1.6 | 「有利」 | 浅绿 #a8e6a0 | 无 |
| 0.85 ~ 1.15 | （不飘字） | — | 无 |
| 0.6 ~ 0.85 | 「被克」 | 灰蓝 #8ab4d8 | 无 |
| < 0.6 | **「无效！」** | 深灰 #6b7078 | 音效 `hit_wood` |

**为什么不全部飘字**：现状注释已经发现了这个问题——
> 基础克制 +35% 几乎每一下都在发生，飘字会瞬间刷屏。

30v30 时每秒几十次命中。**只在"值得注意"的档位飘字**，是这条经验的直接延续。

### 3.2.1 单位护甲标识

在单位血条左侧画一个 5px 的小图标表示护甲类型：

| 护甲 | 图标 | 形状 |
|---|---|---|
| 无甲 | 无图标 | — |
| 轻甲 | 单个 ^ |
| 重甲 | 双 ^^ | 更厚 |
| 建筑 | 城墙垛口 | 城墙专属 |
| 英雄 | 星 | 英雄专属 |

> **成本极低（每个单位多 1 次 fillRect），但让"看护甲配兵"从不可能变成可能。**

### 3.2.2 战前提示（守城模式专属）

每波开始前，波次预告显示：**「本波敌军：重甲 ×8 / 轻甲 ×4 / 攻城器 ×2」**

这是守城模式相对竞技场最大的优势——**敌人组成是可知的，你可以针对性配兵**。
v3 企划里写过这条价值，但当时没有双轴，"针对性"只能选兵种；有了双轴，还能针对性选**攻击类型**。

## 3.3 克制与战术卡的交互

现有 PERKS 里有一张「克敌机先」（`counterBonus +0.15`）。

双轴上线后，这张卡的作用范围需要**明确界定**——否则会出现"克制加成到底加在哪一层"的歧义：

| 方案 | 效果 | 评价 |
|---|---|---|
| 只加三元环层 | 1.35 → 1.50 | ✅ **推荐**。语义清晰："克敌机先"= 更会打克制 |
| 加最终倍率 | (ring × matrix) × 1.15 | ❌ 会让"打错目标"也吃到加成，语义模糊 |
| 加矩阵层 | matrix × 1.15 | ❌ 玩家无法理解 |

**决策：只作用于三元环层。** 并在卡面描述里写清楚：「三元环克制伤害额外 +15%」。

> 这是一个典型的"系统打架"案例：新系统上线后，旧系统的语义必须重新界定。
> 不界定就会出现"玩家以为加在哪、代码加在别处"的经典事故。

# §4. 经济系统深化

## 4.1 现状 Sources / Sinks 全景

### Sources（5 条，实测）

| # | 来源 | 数值 | 定位 |
|---|---|---|---|
| 1 | 税收（被动） | `taxBase: 10.2` + `taxPerMine: 0.9`/级 | 保底 |
| 2 | 击杀掉金 | 小兵 5 / 精英 20 / Boss 100 | 战斗即经济 |
| 3 | 波次奖励 | `40 + 12×波次` | 稳定增长 |
| 4 | 存款利息 | 6%，上限 60（银行可升到 18% / 180） | 复利 |
| 5 | 完美防守 | +50（本波零阵亡） | 技巧奖励 |

### Sinks（4 条，实测）

| # | 出口 | 数值 | 定位 |
|---|---|---|---|
| 1 | 买兵 | 45-160，×1.06-1.08 递涨 | 即时战力，会死 |

| 3 | 城墙 | 升级 220-2400；修复 0.22 金/HP | 容错 |
| 4 | 经济建筑 | 金矿 160-1500 / 市场 260-1500 / 银行 420-2500 | 延迟满足 |

## 4.2 诊断：两个真问题

### 问题 1：后期金币溢出（v3 自己就担心过）

v3 的数值推演表：

| 波次 | 玩家累计收入 |
|---|---|
| 10 | ~3,400 |
| 15 | ~9,000 |
| 20 | **~20,000** |

而 sinks 的上限：

| Sink | 买满的总花费 |
|---|---|
| 科技（3 系 × 4 级）= 12 次升级 | 约 3,480 |
| 城墙（Lv1→Lv5）= 4 次升级 | 4,220 |
| 经济建筑全满 | 约 8,330 |
| **合计** | **约 16,000** |

**买兵是唯一的"无上限 sink"**，但它的价格递涨（×1.06）意味着第 30 个近战要 45×1.06²⁹ ≈ 244 金——还能吃钱，可是**兵力有实际价值上限**（同屏 50 敌，玩家 30 兵已经足够）。

> **结论：第 15 波之后，钱开始没处花。** 这就是 v3 §10 风险表第一条"经济膨胀失控"的现实版本。

### 问题 2：第 10 波后决策密度下降

前 10 波每一波都在"买兵还是升科技还是建金矿"之间纠结。
第 10 波后科技满了、建筑满了、兵够用了 —— **剩下的钱只能无脑买兵，经营决策消失**。

## 4.3 解法：三个新 Sink

| # | 新 Sink | 吃掉的钱 | 为什么它是好 sink |
|---|---|---|---|
| **S5** | **英雄养成**（§5.5） | 局内 8,000-15,000 | **最好的 sink**：无上限、有成长感、玩家主动想花钱 |
| **S6** | **消耗品 / 战地补给** | 每波 200-800 | 波动性 sink，逼玩家每波做小额决策 |
| **S7** | **雇佣兵（限时单位）** | 每波 300-1,200 | 提供"这一波特别难"的针对性解法 |

### 4.3.1 S5 英雄养成（详见 §5.5）

英雄等级 + 技能等级 + 装备，是**无上限的金币黑洞**，且玩家心甘情愿往里投。
这是所有带养成的塔防/自走棋验证过的规律。

### 4.3.2 S6 消耗品（战地补给）

每波备战期可购买，**只在本波生效**：

| 道具 | 价格 | 效果 | 决策张力 |
|---|---|---|---|
| 应急修缮 | 180 | 立即修复城墙全段 15% | 救火 vs 买兵 |
| 战地医疗 | 220 | 本波全体单位每秒回 1% 最大 HP | 续航 vs 输出 |
| 磨刀石 | 260 | 本波全体攻击 +12% | 进攻 vs 防守 |
| 急行军 | 200 | 本波全体移速 +25% | 出击流专用 |
| 铜墙铁壁 | 300 | 本波城墙受伤 −30% | Boss 波专用 |

> **为什么是"本波生效"而不是永久**：
> 永久增益会滚雪球（越早买越赚，变成必选）；
> 本波生效则每一波都要重新回答"这一波值不值得花钱"——**决策密度回来了**。

### 4.3.3 S7 雇佣兵

| 雇佣兵 | 价格 | 效果 |
|---|---|---|
| 流浪剑客 | 320 | 一个 Lv5 近战，本波结束后离场 |
| 神射手小队 | 380 | 3 个 Lv4 远程 |
| 重甲卫队 | 450 | 2 个 Lv5 大盾步兵 |
| **传奇佣兵** | 800 | 一个随机 Lv5 分支单位 + 自带晋升（老兵） |

> **"本波结束后离场"是关键**：不占常驻兵力、不影响长期养成曲线，
> 纯粹是"这一波顶不顶得住"的应急选项。

## 4.4 通胀推演（修正后）

|---|---|---|---|
| **S6** | 战地回收 | 每波结束，回收阵亡单位装备：`阵亡数 × 8 金` | **给"敢死流"一条经济回报**。现在的阵亡是纯损失，导致玩家不敢出击；有了回收，"用命换钱"成为可行策略 |

# §5. 英雄系统

## 5.1 三个候选方案的取舍

| 方案 | 描述 | 优点 | 缺点 | 判定 |
|---|---|---|---|---|
| **A · 光环型** | 英雄不上场，只提供被动光环 + 主动技能 | 实现最简；不会被秒；不破坏阵型 | **没有情感投射**。玩家看不见"我的英雄"，P2 支柱落空 | ❌ |
| **B · 超级单位** | 英雄作为一个强力单位上场，技能自动放 | 有存在感；战斗爽 | 玩家对技能没有掌控感，又是一个"看戏"元素 | ❌ |
| **C · 上场 + 光环 + 手动大招** | 上场单位 + 常驻光环 + 玩家手动放的大招 | 存在感 + 掌控感 + 战略深度 | 与现有指令系统争夺操作带宽 | ✅ **推荐** |

**选 C，但必须解决"操作带宽争夺"——这是 §5.3。**

## 5.2 对称性：这是最难的一题

### 5.2.1 问题的本质

英雄是"玩家养成的"（跨局 Meta 成长）。如果敌方英雄也是玩家养成的强度，
那玩家的养成就没有意义；如果敌方没有英雄，那就是纯粹的白赚。

### 5.2.2 解法：对称的是"能力框架"，不是"获取路径"

| 维度 | 玩家英雄 | 敌方英雄 | 是否对称 |
|---|---|---|---|
| 能力框架（光环 + 大招 + 属性） | 同一套公式 | 同一套公式 | ✅ **对称** |
| 上场位置 | 阵型中后排 | 阵型中后排 | ✅ 对称 |
| 强度来源 | 局内金币升级 + Meta 天赋 | 按波次/回合配置的等效等级 | ✅ **数值等效** |
| 获取路径 | 玩家选择 + 养成 | 系统配置 | ❌ **故意不对称** |

**核心原则**：

> **玩家的英雄比敌人的强，是因为玩家"花金币升级了"，不是因为"玩家有英雄"。**

如果玩家一分钱不投，他的英雄应该和敌方英雄**五五开**。
这保留了养成的意义，同时守住了 P4「对称即公平」。

### 5.2.3 敌方英雄配置

| 模式 | 敌方英雄 |
|---|---|
| **守城远征** | Boss 波（5/10/15/20）出英雄；普通波无。第 20 波英雄 = 玩家满级英雄的 90% |
| **竞技场** | 每轮都有，AI 随机选一个（镜像玩家的选择数量） |
| **镜像试炼** | 双方同英雄同等级 —— **终极对称，也是平衡测试场** |

## 5.3 ⚠️ 与指令系统的冲突（系统交互矩阵）

### 5.3.1 冲突描述

| 系统 | 玩家操作 | 频率 | 性质 |
|---|---|---|---|
| 指令（v4 扩到 6 条） | 选指令 → 点战场 | 每 7-15s 一次 | 常规战术 |
| 英雄大招 | 按键 → 放 | 每 45-60s 一次 | 战略技能 |

**两者都是"玩家主动释放的能力"，争夺同一份注意力。**

### 5.3.2 解法：分轨，不共享资源

**决策：英雄大招走独立的「士气值 / Morale」资源，不消耗 CP。**

| | 指令系统 | 英雄大招 |
|---|---|---|
| 资源 | CP（共享池，10 点上限） | 士气（独立条，0-100） |
| 回复 | 每秒 +0.28，击杀 +0.25 | 每秒 +1.6，击杀 +3，承受伤害 +2 |
| 频率 | 每 7-15s | **每 45-60s** |
| 决策性质 | 战术（这发砸哪） | 战略（这一波要不要交） |

**为什么不共享 CP**：

> 如果共享，玩家的最优解永远是"攒 CP 给英雄大招"——6 条指令全部变成摆设。
> 一个系统吃掉另一个系统，是设计事故，不是设计。

**分轨后的节奏**：

```
0s    ─ 指令（落雷）
8s    ─ 指令（冲锋号）
15s   ─ 指令（冰封）
22s   ─ 指令（火墙）
30s   ─ 指令（落雷）
45s   ─ ★英雄大招（士气满）
52s   ─ 指令（治疗波）
...
```

**每 45 秒一次的大决策，中间穿插 5-6 次小决策。** 这是有节奏的操作曲线，不是平铺。

### 5.3.3 系统交互矩阵（新增系统 × 现有系统）

| | 三元环 | 分支 | 经济 | 指令 CP | 城墙 | 驻守/出击 |
|---|---|---|---|---|---|---|
| **双轴克制** | ✅ intended（相乘叠加） | ✅ intended（分支改攻防类型） | ⚠️ acceptable（弩车是经济 sink） | ✅ intended（魔法指令挂状态） | ✅ **intended**（攻城类型专拆墙） | ✅ intended |
| **特殊编制** | ✅ intended（中性不入环） | ✅ intended | ✅ intended（新 sink） | ✅ intended | ⚠️ acceptable（爆破手拆墙） | ⚠️ acceptable |
| **英雄大招** | ✅ intended（光环加成） | ✅ intended（英雄可强化分支） | ✅ **intended**（养成吃金币） | ⚠️ **风险点**（见 §5.3.2） | ✅ intended（铁壁将军修墙） | ✅ intended（跟随 stance） |
| **英雄光环** | ✅ intended | ⚠️ acceptable（可能让某分支过强） | ⚠️ acceptable | ✅ intended | ✅ intended | ✅ intended |

**唯一的红色风险点就是"英雄大招 × 指令 CP"，已用分轨解决。**

## 5.4 六英雄详细设计

### 5.4.1 英雄通用框架

| 属性 | 数值 | rationale |
|---|---|---|
| 基础 HP | 同等级近战 ×4 | 能扛住 3-4 个单位的集火约 8 秒，够玩家反应 |
| 基础攻击 | 同等级近战 ×2.2 | 输出约等于 2 个兵，但不是"一打十" |
| 护甲类型 | **hero** | 独立护甲，魔法 ×0.85（防秒杀） |
| 攻击类型 | 随英雄 | — |
| 移速 | 200（介于近战 160 与骑兵 300 之间） | 能跟上大部分阵型，但追不上骑兵 |
| 站位 | 阵型中后排，跟随 stance | 复用现有 stance 系统，零新架构 |
| 阵亡 | **不死亡，退场**（30s 后以 50% HP 返场） | 见下方 rationale |

**为什么英雄"退场"而不是"死亡"**：

> 如果英雄会死，玩家的最优解是"永远不出击"（保英雄）→ 与 v3 的"驻守/出击"张力冲突，
> 且一次失误就失去英雄 = 惩罚过重，会产生挫败感。
>
> **退场 30 秒**是一个"有时间代价但非毁灭"的惩罚：
> 玩家会为了保住英雄而调整站位（增加决策），但不会因为一次失误而想重开。

| 攻击类型 | blunt（钝击，锤盾） |
| 护甲类型 | hero |
| **光环** | 半径 180 内友军**受伤 −12%** |
| **大招 · 不动如山** | 5 秒内：范围内友军**免疫击退**、城墙立即修复 15% 最大 HP、自身受伤再 −30% |
| 士气消耗 | 100（满） |
| CD | 50s |

**设计意图**：他是"墙要破了"这个时刻的答案。
城墙是 v3 的第二血条，铁壁将军是**唯一能主动修墙的英雄**——这让他有不可替代性。
"驻守流"的核心张力（守着不出去 vs 出去刷钱）在他身上得到强化。

**数值 rationale**：
- 光环 −12%：低于 PERKS「铁血纪律」的 +15% HP。
  **减伤 12% ≈ 有效 HP +13.6%**，与那张卡接近但略低——因为光环是范围性的，覆盖面更广，单体价值要打折。
- 大招修墙 15%：Lv5 城墙单段 3700 HP，15% = 555 HP，等效于省下 122 金（0.22 金/HP）。
  **加上免疫击退的战术价值，总价值约 300-400 金** —— 与一个"雇佣兵"相当，合理。

#### ② 疾风游侠（Mobility / 骑兵流）

| 项 | 规格 |
|---|---|
| 定位 | 机动核心。出击流的答案 |
| 攻击类型 | pierce |
| **光环** | 全体**骑兵移速 +15%、冲锋伤害 +10%** |
| **大招 · 疾风突袭** | 全体骑兵立即进入冲锋状态（无视当前 CD），首次撞击伤害 ×2，持续 4s |
| 士气消耗 | 100 |
| CD | 45s |

**设计意图**：她是"敌人远程在后面输出"这个时刻的答案。
骑兵的定位是切后排，但现状骑兵要跑过去——疾风突袭让"切后排"从"慢慢跑"变成"瞬间到达"。

**与飞镰游骑的协同**：飞镰游骑（scythe）专克远程 ×2.4，疾风突袭让全体骑兵冲锋撞击 ×2。
**两个 ×2 相乘 = 一次能打掉远程部队的冲锋。** 这是"组合技"的设计——让玩家感到"我配对了"。

> **注意这是乘法叠加，要防爆炸**：2.4 × 2.0 = 4.8 倍。
> 为了不让疾风游侠成为骑兵流唯一解，冲锋 ×2 **只在撞击瞬间生效一次**（不是持续 4s），
> 且飞镰游骑本身 HP ×0.8（脆），冲过去回不来。

#### ③ 神机军师（Ranged / 输出流）

| 项 | 规格 |
|---|---|
| 定位 | 输出核心。驻守流的另一个答案 |
| 攻击类型 | pierce |
| **光环** | 全体**远程射程 +12%、攻速 +8%** |
| **大招 · 神机齐射** | 全体远程立即进行一次齐射（无视攻击 CD），且本轮齐射必定触发克制判定 |
| 士气消耗 | 100 |
| CD | 48s |

**设计意图**：远程的弱点是"攻击间隔"（0.85-1.05s）。齐射让所有远程在同一瞬间打出一轮，
制造**一次性的爆发窗口**——视觉上是"万箭齐发"，机制上是"把持续输出压缩成一击"。

**"必定触发克制判定"的含义**：这一轮齐射无视目标护甲，全部按 1.25 计算。
理由：让大招有"确定性价值"，而不是"打在重甲上还是 0.75"。

> 反面案例：如果齐射不吃任何加成，玩家放了之后发现"打在枪骑兵身上还是不疼"，
> 大招的仪式感就毁了。**大招必须让玩家感到"这一下不一样"。**

#### ④ 炼金术士（Economy / 刷钱流）★ 与经济系统耦合

| 项 | 规格 |
|---|---|
| 定位 | 经济核心。**唯一一个直接产出资源的英雄** |
| 攻击类型 | magic |
| **光环** | **击杀掉金 +20%**、战场金币自动拾取范围 ×2 |
| **大招 · 点石成金** | 立即获得**当前存款的 8%**作为金币（下限 150，上限 900） |
| 士气消耗 | 100 |
| CD | **60s**（最长，因为产资源） |

**设计意图**：他是"出击刷钱流"的答案，也是**把英雄系统和经济系统焊在一起的那颗钉子**。

**数值 rationale（这是全表最需要算的一格）**：

| 场景 | 存款 | 大招收益 | 等效于 |
|---|---|---|---|
| 前期（W5） | 800 | 150（触下限） | 约 30 个小兵的击杀金 |
| 中期（W12） | 4,000 | 320 | 约 1.5 次科技升级 |
| 后期（W20） | 12,000 | 900（触上限） | 约 2 个雇佣兵 |

**为什么是 8% 而不是固定值**：
- 固定值 → 前期逆天、后期无感
- 百分比 → **自带复利**，与"银行利息"经济流派天然协同（存款越多，大招越值）
- 上限 900 → 防止后期一次大招顶一波收入

**为什么 CD 最长（60s）**：产资源的技能如果 CD 短，会挤压其他所有英雄的生存空间。
**60s 意味着一局 25 分钟最多放 20-25 次，理论总产出约 8,000-12,000 金** ——
正好是 §4.2 算出的"后期溢出金额"。**他一个人吃掉了通胀。**

> 这就是 §1.2 说的"英雄是经济的新 sink"的反向版本：
> 炼金术士是 **source**，英雄养成是 **sink**，两者形成闭环。

#### ⑤ 狂战士（Burst / 爆发流）

| 项 | 规格 |
|---|---|
| 定位 | 爆发核心。出击流 |
| 攻击类型 | slash |
| **光环** | 友军**大招触发率 +20%**（相对值，7% → 8.4%） |
| **大招 · 血怒** | 8 秒内：全军攻速 +30%、攻击 +15%，**但受伤 +20%** |
| 士气消耗 | 100 |
| CD | 50s |

**设计意图**：他是"这一波顶不住了，赌一把"的答案。
**带负面代价的增益**是让决策成立的关键——没有代价的 buff 是无脑按，有代价才是决策。

**数值 rationale**：
- 攻速 +30% + 攻击 +15% ≈ **DPS +49.5%**
- 受伤 +20% → 敌方 DPS 相对 +20%
- **净收益 ≈ +24%**，持续 8 秒。够扭转一波，不够无脑赢。
- 光环 +20% 大招率：`CONFIG.skillChance 0.07 → 0.084`。
  30 兵时从 2.1 次/秒 → 2.52 次/秒，**感知明显但不刷屏**（守住 P1）。

#### ⑥ 暗影刺客（Assassin / 斩首流）

| 项 | 规格 |
|---|---|
| 定位 | 斩首核心。切后排 |
| 攻击类型 | slash |
| **光环** | 无（**唯一没有团队光环的英雄**）—— 换来自身移速 +40%、优先索敌敌方远程/医师 |
| **大招 · 斩首** | 瞬移到**敌方当前攻击力最高的单位**身后，造成 `自身攻击 ×6` 伤害，并使其沉默 3s |
| 士气消耗 | 100 |
| CD | 45s |

**设计意图**：他是"敌方后排有个医师在奶全军"这种局面的答案。

**为什么他没有团队光环**：
> 这是**故意的设计缺陷**。六英雄里五个有光环，唯独他只强化自己——
> 代价换来的是**最高的单体爆发**（×6 倍率，全英雄最高）。
> 玩家必须回答："我要一个让全军变强的英雄，还是一个能秒掉关键目标的英雄？"
> **这就是 P3「没有唯一解」在英雄选择层面的兑现。**

**斩首的目标选择逻辑**：当前攻击力最高的单位（通常是最高等级单位或英雄）。
**沉默 3s**：不能放技能。这让斩首有"打断"的战术价值，不只是伤害。

开局前选 1 个英雄。**选择即流派宣言**：

| 你选 | 等于你在说 |
|---|---|
| 铁壁将军 | 我要龟缩，靠墙和远程磨死对面 |
| 疾风游侠 | 我要主动出击，用骑兵切后排 |
| 神机军师 | 我要靠远程火力覆盖 |
| 炼金术士 | 我要滚经济，用钱砸死对面 |
| 狂战士 | 我要速战速决，赌爆发 |
| 暗影刺客 | 我要精准斩首，打掉关键点 |

**这个界面本身就是最好的新手引导** —— 玩家不需要看教程，
"我想怎么玩"这个直觉就能帮他选对英雄。

## 5.5 英雄养成（经济 Sink 的主体）

### 5.5.1 三层养成

| 层 | 内容 | 消耗 | 节奏 |
|---|---|---|---|
| **局内等级** | Lv1-Lv5，每级提升光环强度与大招倍率 | 金币：300 / 700 / 1,500 / 3,000 / 6,000 | 一局内 |
| **技能强化** | 3 个强化槽（光环 / 大招 / 生存），每槽 3 级 | 金币：500 → 1,200 → 2,500 | 一局内 |
| **Meta 解锁** | 解锁新英雄、解锁强化槽 | 军功（跨局） | 跨局 |

**局内满养成总花费**：`11,500（等级）+ 3×4,200（技能）= 24,700 金`

对比 §4.2 的"第 20 波累计收入 20,000" —— **英雄养成能吃掉比玩家全部收入更多的钱。**

> 这意味着玩家**永远养不满英雄**，必须在"养英雄"和"买兵/科技/城墙"之间持续取舍。
> 这就是 P3「钱永远不够花」在有了英雄之后的样子。
> `[PLACEHOLDER · 24,700 是纸面值，需在 Monte Carlo 里验证。
> 若实测玩家在第 15 波就养满英雄，说明成本太低，曲线改为 400/900/1900/3800/7500。]`

### 5.5.2 养成曲线与波次的对应

| 波次 | 预期英雄等级 | 累计养成投入 |
|---|---|---|
| 5 | Lv2 | 1,000 |
| 10 | Lv3 + 1 个强化 | 3,200 |
| 15 | Lv4 + 2 个强化 | 7,900 |
| 20 | Lv5 + 3 个强化（满） | 24,700 |

**关键**：这条曲线与"波次难度曲线"（`budgetGrowth 1.22`）必须**同步上升**。
如果英雄成长快于敌人成长 → 后期无脑；慢于 → 后期绝望。

> **验收方法**：Monte Carlo 跑"均衡策略"200 局，
> 看第 5/10/15/20 波的通过率是否落在 **85% / 65% / 45% / 30%** 附近。
> 偏离超过 ±10% 就调养成成本或英雄强度。

## 5.6 敌方英雄（对称性的落地）

### 5.6.1 守城模式

| 波次 | 敌方英雄 | 等效强度 |
|---|---|---|
| 5（Boss） | 随机英雄，Lv2 | ≈ 玩家 Lv2 未强化 |
| 10（Boss） | 随机英雄，Lv3 + 1 强化 | ≈ 玩家 Lv3 |
| 15（Boss） | 随机英雄，Lv4 + 2 强化 | ≈ 玩家 Lv4 |
| 20（Boss） | **固定的"深渊统帅"**，Lv5 + 3 强化 | **= 玩家满级的 90%** |

**第 20 波故意只有 90%**：给玩家留 10% 的"我练了、我配对了、我赢了"的空间。
**终局应该是"险胜"，不是"势均力敌"或"碾压"。**

### 5.6.2 竞技场模式

AI 随机选择一个英雄，**等级锁定为与玩家英雄相同**。
（竞技场是快速局，不该有养成差。）

### 5.6.3 镜像试炼

双方**同英雄、同等级、同强化**，胜负 100% 由指挥决定。

> **这是验证 §0 修复是否成功的最强工具。**
> 如果镜像模式下胜率不是 50% ± 4%，说明还有隐藏的不对称没挖出来。

# §8. 验收与失败信号

## 8.1 对称性（最高优先级）

| 检查 | 方法 | 通过线 |
|---|---|---|
| 增益双侧生效 | 强改 `G.enemyMods.hpMul = 2` | 敌人血量 ×2 |
| 镜像胜率 | 镜像试炼 200 局 | **50% ± 4%** |
| 随机选卡胜率 | 竞技场 200 局 | **52-56%**（从 67% 降下来） |
| 英雄不白赚 | 玩家 0 投入英雄 vs 敌方同级英雄，100 局 | **50% ± 5%** |

## 8.2 兵种与克制

| 失败信号 | 表现 | 诊断 |
|---|---|---|
| 矩阵被无视 | 玩家只按三元环配兵，从不看护甲 | 可视化不足 → 加战前提示与飘字强度 |
| 单一攻击类型统治 | >60% 的局只出一种攻击类型 | 某行矩阵和过高 → 下调 |
| 攻城器当主力 | 弩车被大量用于打单位 | 攻城→单位 从 0.5 降到 0.35 |
| 特殊编制必选 | 鼓手 100% 出场率 | 削光环或提价格 |

## 8.3 经济

| 失败信号 | 表现 | 诊断 |
|---|---|---|
| 后期溢出 | 第 15 波后结余 > 15% 收入 | 英雄养成成本太低 → 提曲线 |
| 前期窒息 | 第 5 波前买不起兵 | 消耗品价格太高 → 降或推迟解锁 |
| 决策消失 | 第 12 波后玩家不再犹豫 | 新 sink 不足 → 加消耗品种类 |

## 8.4 英雄

| 失败信号 | 表现 | 诊断 |
|---|---|---|
| 唯一解 | 某个英雄 >70% 选择率 | 削光环或加针对性克制 |
| 大招无感 | 玩家忘记放大招 | 士气累积太慢 → 提到 2.2/s |
| 指令被吃 | 有英雄后指令使用率下降 >40% | **分轨失败** → 拉长大招 CD |
| 英雄抢戏 | 玩家只关注英雄，不关心军团 | 英雄输出过高 → 从 ×2.2 降到 ×1.8 |

# §10. `damageUnit` 结算顺序（三个系统共用的契约）

这是 §9-R8 的解法。三个系统都要改伤害结算，**必须先定死顺序**：

```js
function damageUnit(target, rawDmg, attacker, knock, knockY) {
  // ① 攻方倍率：三元环 × 双轴矩阵 × 战术卡 counterBonus
  const ring   = counterMul(attacker, target);        // 内部已走 modsOf
  const matrix = AT_VS_ARMOR[attacker.atkType][target.armorType];
  let   mul    = ring * matrix;

  // ② 攻方增益：英雄光环 / 战术卡 / 连杀 / 士气
  mul *= heroAuraMul(attacker);                       // 玩家与敌方英雄都走这里
  mul *= comboMul(attacker);

  // ③ 守方减伤：英雄光环 / 城墙 / 驻守加成 / 消耗品
  mul *= (1 - heroAuraReduce(target));
  mul *= stanceReduce(target);

  // ④ 硬上限截断（R3 兜底）
  mul = Math.min(mul, 4.0);

  // ⑤ 状态层（v4）：护盾吸收 → 破盾 → 处决判定
  // ⑥ 落血 → 死亡结算 → 晋升/连杀/金币
}
```

**契约要点**：
1. **①②③ 全部走 `modsOf(side)` 或 `heroOf(side)`，禁止出现 `side === "player"` 字面量。**
   —— 这是 §0 的形式化防线，加一行 lint 规则即可强制执行。
2. **④ 的硬上限 4.0 是安全阀**，防止任何组合爆炸。
3. ⑤⑥ 留给 v4 的状态系统与 v3 的经济系统。

> **建议：把「禁止 `side === "player"` 字面量」写成一条 ESLint 规则或 build 期检查。**
> 靠人记住一定会忘，靠工具才靠得住。这是 §0 那个 bug 的根因——
> 注释写了"必须走 modsOf"，但没人强制执行。
